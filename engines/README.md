# Движки персонажей

| Движок | Формат | Чем рисуется | Нужно дополнительно |
|---|---|---|---|
| `gif` (стандартный) | GIF / PNG-кадры / спрайт-лист, рисованные краб, кот, робот | tkinter (`mascot.py`) | ничего, работает всегда |
| `live2d` | Cubism 3 / 4 / 5: папка с `*.model3.json` + `.moc3` + текстуры | pixi.js 6 + pixi-live2d-display 0.4 (MIT) в окне WebView2 | `pywebview`, Edge WebView2 Runtime, **ваш** `live2dcubismcore.min.js` |
| `vrm` | VRM 0.x и 1.0 (`.vrm`, это GLB) | three.js + @pixiv/three-vrm 3.x (MIT) в окне WebView2 | `pywebview`, Edge WebView2 Runtime |

Не поддерживается: Cubism 2 (`.model.json`, `.moc`), VRM-файлы без гуманоида (`hips`, `head`), обычные GLB, FBX/MMD. VTube Studio здесь не движок: это отдельная программа, мы её не используем и не запускаем.

## Как это устроено
- Выбор: `config.json: character` указывает на папку персонажа; если в её `character.json` есть `"engine": "live2d" | "vrm"`, `mascot.py` запускает процесс отрисовки (`engines/web_child.py`), иначе рисует сам.
- Процесс отрисовки: локальный сервер `127.0.0.1` со случайным токеном в пути (раздаёт только страницу, `vendor/`, выбранный Cubism Core и папку модели) + безрамочное окно WebView2 с настоящей попиксельной прозрачностью (форма чёрная + `DwmExtendFrameIntoClientArea`). Управление: JSON-строки в stdin, события в stdout (`engines/webhost.py`).
- Любая проблема (нет pywebview, нет Cubism Core, битая модель, процесс упал, не загрузилась за 30 с) = возврат к стандартному персонажу (краб/выбранный base) и сообщение в облачке; `Mascot.engine_status` показывает причину.
- Эмоции: 10 состояний (idle, listening, recognizing=transcribing, thinking, working, speaking, success, error, clarification=question, sleeping=sleep) + confirm. Для каждой профиль в `engines/profiles.py`: выражение (VRM: по пресетам happy/sad/surprised/relaxed, Live2D: по ключевым словам в именах выражений), движение (Live2D-группа), рот при речи, моргание и процедурное покачивание (bob / sway / tilt / pulse), которое работает даже у модели без выражений. Переопределения для модели: `character.json` -> `"emotion_profile": {"success": {"expression": "F01", "motion": "TapBody"}}`.
- Моргание: VRM `blink`, Live2D группа EyeBlink или `ParamEyeLOpen/ROpen`; сон = закрытые глаза. Рот при речи: VRM `aa`, Live2D `LipSync`/`ParamMouthOpenY` (имитация по синусу, не по аудио). Нет такого параметра: покачивание головы.

## Режимы окна
- Плавающее окно (по умолчанию): поверх обычных окон; перетаскивание мышью, правый клик = меню.
- Desktop pet (`window_mode: pet`): окно стоит на нижней кромке рабочей области (над панелью задач), после перетаскивания возвращается, `pet_patrol` = гулять по кромке в покое.
- Безрамочные игры (`compat_mode: borderless_game`): каждые 2 с повторно ставится «поверх всех» (`SetWindowPos`), чтобы игра в borderless windowed не перекрыла персонажа.
- `fullscreen_policy`: `exclusive` (по умолчанию) скрывает персонажа, когда оболочка сообщает о D3D exclusive fullscreen / режиме презентации (`SHQueryUserNotificationState`), `any` скрывает в любом полноэкранном приложении, `never` не скрывает.
- Клики сквозь прозрачные места (`click_through`, по умолчанию вкл.): страница раз в 200 мс присылает маску непрозрачных пикселей, процесс отрисовки опрашивает курсор и переключает `WS_EX_LAYERED | WS_EX_TRANSPARENT`; мимо модели клик попадает в окно под ней. Правый клик и перетаскивание работают на самой модели.
- Прогрев (`prewarm_engine`, по умолчанию вкл., если установлена хотя бы одна модель): процесс WebView2 стартует скрытым через 2,5 с после запуска и держится между моделями, смена модели не ждёт запуска браузера.
- DPI: процесс отрисовки per-monitor aware, координаты в физических пикселях как у Tk (проверено на мониторе 125%).
- Рот при речи: амплитуда (RMS) воспроизводимого TTS-аудио по кускам по 40 мс (`engines/lipsync.py`), без аудио - собственная имитация.
- Экономия: `anim_enabled: false` = статичная поза (рендер только при смене эмоции), `render_fps` 10-60, `model_scale` 40-200 %.
- Только документированные API Windows. Нет инъекций в процессы, хуков, перехвата ввода, обхода античита. Поверх игр в эксклюзивном полноэкранном режиме рисовать нельзя ничем из этого, мы этого не обещаем.

## Лицензии
- three.js (MIT), @pixiv/three-vrm (MIT), pixi.js (MIT), pixi-live2d-display (MIT): собраны в `engines/web/vendor/`, тексты лицензий лежат рядом (`LICENSE.*.txt`). Сборка: `cd engines/web && npm install && npm run build`.
- `cubism4.min.js` (pixi-live2d-display) включает код Cubism Framework под Live2D Open Software License.
- **Live2D Cubism Core** (`live2dcubismcore.min.js`) проприетарный (Live2D Proprietary Software License), в репозиторий не включён и не скачивается: скачайте Cubism SDK for Web на live2d.com, примите лицензию и укажите путь в настройках («Персонажи и движки»). Без файла адаптер Live2D «недоступен», стандартный персонаж работает. Для публикации и коммерческого использования смотрите условия Live2D (лицензия на публикацию зависит от оборота).
- Лицензия модели: VRM хранит условия в метаданных (автор, кто может использовать, коммерческое использование, перераспространение, ссылка на лицензию), они показываются при импорте и в списке. У Live2D-моделей метаданных лицензии нет: показывается README/license из папки модели, если он есть. Условия автора модели всегда проверяйте сами.
